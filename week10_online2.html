요청에 한 줄 더 — 「고쳐도 되는 파일」

영상 ① 의 요청 네 칸에 다섯째 칸을 붙입니다. 대면에서 쓴 세 칸이 그대로 요청이 됩니다.

팀 AI 약속 ① 작업 칸→ 고쳐도 되는 파일

지호: SceneLoader.cs · EnemyPatrol.cs

지호의 요청

- 하려는 것: 게임 오버 뒤 RETRY 를 누르면 처음 상태로 다시 시작하게

- 완료 기준: 점검표 A5 — 게임 오버 뒤 RETRY 하면 처음 상태로 공이 움직인다 · 두 번 연달아 해도 같다 · Console 에 빨간 줄이 없다

- 지금 상황: 코인 3개 → 적에게 닿음 → RETRY → 방향키, 3번 중 3번 공이 안 움직인다. LoadGame 에 Debug.Log 를 찍어 보니 RETRY 뒤 Time.timeScale 이 0

- 하지 말 것: 이름 바꾸기 · 새 Tag · 씬 파일 고치기

- 고쳐도 되는 파일: SceneLoader.cs

답을 받으면 하나부터 봅니다. 바꾼 파일 목록이 「고쳐도 되는 파일」 안에 있는가. 밖이면 넣지 않고 다시 묻습니다.

유니티 안에서 옮기면 .meta 가 같이 움직여 번호가 그대로입니다. 스크립트는 class 이름도 같이 바꿉니다.

밖에서 옮기거나 다시 만들면

탐색기나 AI 도구로 하면 .meta 가 따라가지 않아 번호가 새로 생깁니다. 붙어 있던 오브젝트에 Missing (Mono Script).

넘길 때는 .meta 와 함께

Inspector 칸의 값은 변수 이름으로 저장됩니다

씬 파일에 pointA: {…} 처럼 변수 이름 옆에 값이 적힙니다. 이름을 「더 좋게」 바꾸면 끌어다 놓은 값이 비어 버립니다.

  • · 옛 이름 pointA 로 저장된 값을 새 이름으로 읽어 옵니다
  • · 붙인 줄은 지우지 않고 둡니다
  • · [SerializeField] private 칸도 같습니다

그래서 규칙 파일에 「Inspector 변수 이름은 바꾸지 않는다」를 넣었습니다. 값을 다시 끌어다 놓아도 되지만, 프리팹 · 씬 여러 곳에 쓰였으면 전부 다시 해야 합니다.

묶기 · .unitypackage · 받는 날 · 새 시작점

넘기고 합치는 한 바퀴

깃 없이도 됩니다. 넘기는 단위는 .unitypackage, 합치는 사람은 한 명, 합치는 날은 받는 날입니다.

①
내 Test 씬에서 ✓

넘기기 전에 세 가지 — 점검표 그 줄이 ✓ · 바꾼 파일과 새 Inspector 칸을 내가 말할 수 있다 · 다른 팀원이 한 판

②
묶어서 내보내기

프리팹 + 내 칸 스크립트 → .unitypackage → 팀 공유 폴더 「넘기기」. 이름은 누가_무엇_날짜, 팀 기록에 한 줄

③
받는 날 합치기

합치는 사람이 백업 zip → 가져오기 → Game 씬에 놓기 → Play 로 완료 기준 → 팀 기록

④
새 시작점

합친 프로젝트 zip 을 모두가 받아 내 작업 폴더로. 안 넘긴 작업은 바꾸기 전에 내 .unitypackage 로 묶어 둡니다

예시 팀의 받는 날은 금 11/6 · 일 11/8, 마지막 빌드는 월 11/9. 받는 날에 모인 것만 합치고, 다음 받는 날까지는 새 시작점에서 일합니다.

이상하면 고치려 들기 전에 합치기 전 zip 으로 돌아가, 하나씩 다시 가져옵니다. 어느 묶음에서 문제가 생겼는지 바로 보입니다.

파일을 직접 고치는 AI 를 쓸 때

편집기 안 AI · 터미널 AI(에이전트) · 유니티 도구 연결(MCP)은 붙여 넣기 없이 프로젝트 파일을 바로 바꿉니다. 빠른 만큼, 한 번에 여러 파일이 바뀝니다.

1 내 작업 폴더에서만, 시키기 전에 zip

팀 공유 폴더나 합친 프로젝트에서 바로 돌리지 않습니다.

2 규칙 파일을 읽게

프로젝트 맨 위 AGENTS.md (도구에 따라 이름이 다릅니다). 「팀 약속」이 그대로 적용됩니다.

3 끝나면 바꾼 파일 목록부터

작업 칸 밖 파일, .unity · ProjectSettings · Packages 가 있으면 zip 에서 되돌립니다.

4 옮기기 · 이름 바꾸기는 사람이

Project 창에서 합니다. 도구가 지우고 다시 만들면 .meta 번호가 바뀝니다.

5 유니티로 돌아와 기다리기

도는 표시가 멈출 때까지. 새 파일의 .meta 는 유니티가 만듭니다. 그다음 Console · Play.

6 도구 연결(MCP)은 Test 씬에서

씬을 직접 바꿀 수 있으니, Game 씬은 합치는 사람만 엽니다.

복사 · 붙여 넣기는 사람이 한 번 보고 넣습니다. 직접 고치는 AI 는 끝난 다음에 봅니다. 그래서 바꾼 파일 목록과 되돌릴 zip 이 더 중요합니다.

깃을 쓰는 팀은

이 수업은 깃을 꼭 쓰라고 하지 않습니다. 이미 쓰는 팀만 보면 됩니다. 약속은 그대로이고, 넘기는 단위만 커밋으로 바뀝니다.

.meta 도 커밋

.cs 와 .meta 는 한 쌍입니다. 빠지면 받은 쪽에서 번호가 새로 생깁니다.

올리지 않는 폴더

Library · Temp · Logs · UserSettings 와 빌드 폴더. .gitignore 에 적습니다.

씬은 깃으로도 잘 안 합쳐집니다

씬 주인 약속은 그대로. 남의 씬은 프리팹으로 넘깁니다.

작업 칸마다 브랜치

합치는 사람이 받는 날에 합칩니다. 커밋 메시지는 팀 기록 한 줄처럼.

  • · 유니티는 .meta 번호로 기억 — 이름 · 위치는 Project 창에서
  • · Inspector 값은 변수 이름으로 — 바꾸면 FormerlySerializedAs
  • · 씬은 파일 하나, 주인 한 명 · 설정 · 패키지는 팀에 먼저
02 넘기고 합치기

  • · 내 칸 파일만 .unitypackage, 이름은 누가_무엇_날짜
  • · 받는 날 — 백업 → 가져오기 → Game 씬 → Play → 팀 기록

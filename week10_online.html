using UnityEngine.SceneManagement; void EndGame(bool cleared) { GameResult.cleared = cleared; // 다음 장 GameResult.score = count; SceneManager.LoadScene("Result"); } // SetCountText 안 — 다 모았을 때 if (count >= 12) { EndGame(true); } // OnCollisionEnter 안 — 적에 닿았을 때 EndGame(false); // 떨어졌을 때 void Update() { if (transform.position.y < -10f) { EndGame(false); } }

다시 하기 — 시간부터 되돌립니다

다시 시작했더니 공이 멈춰서 안 움직이는 문제가 자주 나옵니다.

끝날 때 Time.timeScale = 0 으로 멈춰 두었다면, 그 값은 씬을 다시 불러와도 그대로입니다.

timeScale 을 쓰지 않았다면 이 줄은 있어도 아무 해가 없습니다.

한 판 점검 — Title 에서 Play

Game 씬을 연 채 Play 를 누르면 Title 을 건너뜁니다. Project 창에서 Title 을 더블클릭해 열고 누르세요.

START 를 누르면 Game 으로 넘어간다

다 모으면 Result 에 CLEAR! 와 점수가 보인다

지면 Result 에 GAME OVER 가 보인다

RETRY 를 누르면 처음 상태로 돌아가고, 공이 움직인다

TITLE 을 누르면 시작 화면으로 돌아간다

하는 중에 Esc 를 누르면 시작 화면으로 돌아간다

이 여섯 줄이 되면 에디터 안에서는 한 판이 끝까지 돕니다. 이제 빌드해서 에디터 없이 실행해 봅니다.

Ask 와 Agent — 누가 파일을 고치나

입력 칸 아래에서 모드를 바꾸면 Copilot 이 하는 일이 달라집니다.

Ask
답과 코드를 줍니다. 파일은 그대로
  • · 코드를 읽고, 우리가 복사해 넣습니다
  • · 무엇이 바뀌는지 우리 눈에 다 보입니다
  • · 처음에는 이것으로. 이 편은 Ask 로 따라 합니다
Agent
AI 가 파일을 직접 만들고 고칩니다
  • · 끝나면 바뀐 줄을 보여 주고 Keep · Undo 를 묻습니다
  • · 명령을 실행하려 하면 Allow 를 묻습니다
  • · 여러 파일을 한꺼번에 고칠 수 있어서 장치가 더 필요합니다

둘 다 규칙 파일을 읽고, 둘 다 Play 는 못 누릅니다. Agent 로 기능을 더하는 것은 다음 편에서 봅니다.

하네스 — AI 둘레에 두는 장치

AI 가 유니티에서 자주 틀리는 이유

Copilot 은 우리 코드를 읽지만 유니티 화면은 보지 못합니다. 웹 채팅은 붙여 넣은 글이 전부입니다.

씬과 Inspector 를 못 봅니다

스크립트가 어느 오브젝트에 붙었는지, 칸이 비었는지, 태그가 무엇인지 모릅니다.

우리 팀 규칙을 모릅니다

폴더 · 이름 규칙, 누가 어느 씬을 여는지, 입력을 어떤 방식으로 받는지.

우리 유니티 메뉴를 모릅니다

메뉴 이름은 버전마다 조금씩 다릅니다. AI 가 말한 메뉴가 없으면 내 화면에 보이는 이름을 알려 줍니다.

끝났는지 모릅니다

코드를 다 썼다는 것과 게임에서 된다는 것은 다릅니다. Play 는 우리가 누릅니다.

더 똑똑한 AI 로 바꿔도 이 넷은 그대로입니다. 그래서 AI 가 받는 글과 우리가 확인하는 방법을 바꿉니다.

하네스 — AI 둘레에 두는 장치

AI 에게 일을 맡길 때 늘 같이 두는 파일 · 기준 · 순서입니다.

한 번 잘 묻기와 다른 점

질문을 잘 쓰는 것은 그 대화 한 번입니다. 하네스는 파일과 순서로 남아서 다음 대화, 다른 팀원에게도 그대로 갑니다.

틀릴 때마다 고칩니다

AI 가 실수하면 코드만 고치고 끝내지 않습니다. 같은 실수가 다시 안 나오게 장치를 한 줄 고칩니다.

규칙 파일 — AI 에게 먼저 주는 글

팀이 정한 규칙을 파일 하나에 적어 두면, Copilot 이 대화마다 알아서 같이 읽습니다.

.github / copilot-instructions.md
# 우리 팀 규칙 — AI 에게 먼저 주는 파일 ## 우리 게임 - Roll a Ball. 공을 굴려 코인을 다 모으면 클리어, 적에 닿으면 게임 오버 - 씬은 Title · Game · Result. 입력은 Input System (Keyboard.current) ## 폴더 · 이름 - 스크립트는 Assets/Scripts 에. 파일 이름 = class 이름, 영문 · 공백 없이 ## 일하는 방식 - 코드를 주기 전에 무엇을 할지 세 줄로 먼저 말한다 - 한 번에 스크립트 하나만 만들거나 고친다 - 다른 스크립트를 고쳐야 하면 먼저 묻는다 ## 하지 말 것 - 묻지 않은 기능을 덧붙이지 않는다 - 파일을 지우거나 옮기지 않는다. 씬 · 프로젝트 설정은 사람이 유니티에서 바꾼다 ## 팀 약속 — 대면 수업에서 정한 다섯 칸 - ① 작업 칸: 하린 TitleUI.cs / 지호 SceneLoader.cs · EnemyPatrol.cs. 칸 밖의 파일은 고치지 않는다 - ② 씬: Game 씬은 합치는 사람(민준)만 연다. AI 작업은 Test_이름 씬에서 - ③ 이름: 파일 · class · Inspector 변수 이름은 바꾸지 않는다. Tag 는 Player · Enemy · PickUp - ④ 넘기기: 스크립트 + 프리팹을 .unitypackage 로. 합치기는 사람이 한다 - ⑤ 기록: 끝나면 바꾼 파일을 목록으로 알려 준다

완료 기준부터 적습니다

「끝났다」는 AI 가 아니라 우리가 정합니다. 시키기 전에 적어 두면 확인할 때 그대로 씁니다.

이렇게 쓰면

「적이 움직이게 해 줘」

어떻게 움직이면 된 건지 모릅니다. AI 는 코드를 주고 끝났다고 합니다.

이렇게 씁니다
  • Play 하면 적이 두 지점 사이를 초속 3 으로 왕복한다
  • 부딪히면 지금처럼 게임 오버
  • Console 에 빨간 줄이 없다
눈으로 봅니다

Play 를 눌러 맞는지 바로 알 수 있는 문장.

숫자가 있습니다

속도 3 · 코인 12개 · 3초 뒤처럼.

되던 것도 적습니다

「지금처럼」 한 줄이 기존 기능을 지킵니다.

요청은 네 칸으로

칸 이름을 그대로 적고, 뒤에 바로 씁니다. Copilot Chat 에서 줄은 Shift + Enter 로 바꿉니다.

- 하려는 것: 두 지점 사이를 왕복하는 적을 하나 더 만들고 싶어

- 완료 기준: Play 하면 적이 두 지점 사이를 초속 3 으로 왕복한다 · 부딪히면 지금처럼 게임 오버 · Console 에 빨간 줄이 없다

- 지금 상황: 적은 새로 만든 큐브 PatrolEnemy, 태그는 Enemy. 게임 오버는 PlayerController 가 Enemy 태그로 처리하고 있어

- 하지 말 것: PlayerController 는 고치지 마

지금 상황에는

오브젝트 이름 · 붙은 컴포넌트 · Inspector 칸 · 태그. Copilot 은 코드를 읽어도 이것은 못 보니 글로 보여 줍니다.

하지 말 것에는

다른 사람이 맡은 파일, 이미 잘 되는 코드.

질문할 때 붙이는 세 가지, 에러 전문 · 코드 전체 · 무엇을 하려 했는지와 같은 생각입니다. 규칙 파일은 매번 같은 것, 요청 틀은 이번 일만의 것입니다.

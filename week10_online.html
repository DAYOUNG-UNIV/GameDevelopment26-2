다음 주는 알파 테스트입니다

11주차에 다른 팀이 우리 게임을 합니다. 남은 한 주에 AI 를 쓰면 빠르지만, 세 군데에서 시간이 샙니다.

같은 실수를 또 합니다

어제 고쳐 준 것을 새 대화에서 다시 틀립니다. 우리 팀 규칙을 매번 처음 듣기 때문입니다.

다 됐다는데 안 됩니다

AI 는 Play 를 눌러 볼 수 없습니다. 「끝났다」를 정하지 않으면 AI 의 끝과 우리의 끝이 다릅니다.

되돌릴 수 없습니다

여러 파일을 한꺼번에 바꾸고 나서 안 되면, 어디로 돌아가야 할지 모릅니다.

이번 편은 이 셋을 막는 장치를 하나씩 만듭니다. 장치를 만드는 일을 하네스 엔지니어링이라고 부릅니다.

01

시키기 전에

규칙 파일 · 완료 기준 · 요청 틀

AI 가 유니티에서 자주 틀리는 이유

AI 가 받는 것은 우리가 붙여 넣은 글뿐입니다. 유니티 화면은 보지 못합니다.

씬과 Inspector 를 못 봅니다

스크립트가 어느 오브젝트에 붙었는지, 칸이 비었는지, 태그가 무엇인지 모릅니다.

우리 팀 규칙을 모릅니다

폴더 · 이름 규칙, 누가 어느 씬을 여는지, 입력을 어떤 방식으로 받는지.

우리 유니티 메뉴를 모릅니다

메뉴 이름은 버전마다 조금씩 다릅니다. AI 가 말한 메뉴가 없으면 내 화면에 보이는 이름을 알려 줍니다.

끝났는지 모릅니다

코드를 다 썼다는 것과 게임에서 된다는 것은 다릅니다. Play 는 우리가 누릅니다.

더 똑똑한 AI 로 바꿔도 이 넷은 그대로입니다. 그래서 AI 가 받는 글과 우리가 확인하는 방법을 바꿉니다.

하네스 — AI 둘레에 두는 장치

AI 에게 일을 맡길 때 늘 같이 두는 파일 · 기준 · 순서입니다.

한 번 잘 묻기와 다른 점

질문을 잘 쓰는 것은 그 대화 한 번입니다. 하네스는 파일과 순서로 남아서 다음 대화, 다른 팀원에게도 그대로 갑니다.

틀릴 때마다 고칩니다

AI 가 실수하면 코드만 고치고 끝내지 않습니다. 같은 실수가 다시 안 나오게 장치를 한 줄 고칩니다.

규칙 파일 — AI 에게 먼저 주는 글

팀이 정한 규칙을 파일 하나에 적어 두고, AI 와 일을 시작할 때마다 줍니다.

AGENTS.md
# 우리 팀 규칙 — AI 에게 먼저 주는 파일 ## 우리 게임 - Roll a Ball. 공을 굴려 코인을 다 모으면 클리어, 적에 닿으면 게임 오버 - 씬은 Title · Game · Result. 입력은 Input System (Keyboard.current) ## 폴더 · 이름 - 스크립트는 Assets/Scripts 에. 파일 이름 = class 이름, 영문 · 공백 없이 - Game 씬은 합치는 사람만 연다. 실험은 Test_이름 씬에서 ## 일하는 방식 - 코드를 주기 전에 무엇을 할지 세 줄로 먼저 말한다 - 한 번에 스크립트 하나만 만들거나 고친다 - 다른 스크립트를 고쳐야 하면 먼저 묻는다 ## 하지 말 것 - 묻지 않은 기능을 덧붙이지 않는다 - 씬 · 프로젝트 설정을 통째로 바꾸라고 하지 않는다

1
아직 안 되는 것

적이 가만히 있습니다. 「움직이는 적」이 없으면 확인할 수가 없습니다.

2
작게 자른 일

두 지점을 오가는 적 하나. 쫓아오는 적 · 여러 종류는 지금 시키지 않습니다.

3
그 일의 완료 기준

앞 장의 세 줄. 이 세 줄이 맞으면 그 일은 끝입니다.

알파 한 문장에 없는 일은 알파 뒤로 미룹니다. AI 가 빨리 만들어 준다고 범위가 늘어나면, 한 판이 끝까지 도는 것이 늦어집니다.

요청은 네 칸으로

칸 이름을 그대로 적고, 뒤에 바로 씁니다.

- 하려는 것: 두 지점 사이를 왕복하는 적을 하나 더 만들고 싶어

- 완료 기준: Play 하면 적이 두 지점 사이를 초속 3 으로 왕복한다 · 부딪히면 지금처럼 게임 오버 · Console 에 빨간 줄이 없다

- 지금 상황: 적은 새로 만든 큐브 PatrolEnemy, 태그는 Enemy. 게임 오버는 PlayerController 가 Enemy 태그로 처리하고 있어

- 하지 말 것: PlayerController 는 고치지 마

지금 상황에는

오브젝트 이름 · 붙은 컴포넌트 · 관련 코드 전체. AI 가 못 보는 것을 글로 보여 줍니다.

하지 말 것에는

다른 사람이 맡은 파일, 이미 잘 되는 코드.

7주차에 본 에러 전문 · 코드 전체 · 무엇을 하려 했는지와 같은 생각입니다. 규칙 파일은 매번 같은 것, 요청 틀은 이번 일만의 것입니다.

받은 코드, 넣기 전에 읽습니다

한 줄씩 다 이해하지 않아도 됩니다. 네 가지만 봅니다.

EnemyPatrol.cs
using UnityEngine; public class EnemyPatrol : MonoBehaviour { public Transform pointA; // 왕복할 두 지점 public Transform pointB; public float speed = 3f; Transform target; // 지금 가는 쪽 void Start() { target = pointB; } void Update() { transform.position = Vector3.MoveTowards( transform.position, target.position, speed * Time.deltaTime); if (Vector3.Distance(transform.position, target.position) < 0.05f) { target = (target == pointA) ? pointB : pointA; // 도착하면 방향을 바꾼다 } } }
1스크립트가 몇 개인가
2class 이름이 무엇인가

AI 코드를 넣을 때 자주 나는 문제

이럴 때이것부터 봅니다
스크립트가 오브젝트에 안 붙는다파일 이름과 class 이름이 같은지 · Console 에 다른 빨간 줄이 있는지
이름에 빨간 밑줄 (CS0246)맨 위 using 줄이 빠졌는지. AI 에게 「using 까지 전부」 달라고 합니다

빨간 줄이 없으면 — Debug.Log 로 묻습니다

코드가 지나가는 자리에 한 줄을 넣어, 엔진에게 보고를 받습니다.

①
불리나?

함수 맨 위에 한 줄. 안 찍히면 그 함수가 안 불린 것입니다 — Is Trigger · Rigidbody · Tag 부터.

②
값은?

바뀐 바로 다음 줄에서 변수를 찍습니다. 기대한 값과 대어 봅니다.

③
언제 · 무엇과?

몇 번째 프레임인지, 무엇과 닿았는지를 같이 찍습니다. 한 번에 두 번 불리는지가 보입니다.

Play 중에 멈춰서 보기

움직이는 동안에는 못 보는 것을, 멈춰 놓고 봅니다. Play 를 끄지 않고 할 수 있는 것들입니다.

Pause · StepCtrl + Shift + P · Ctrl + Alt + P

위 가운데 두 단추. 멈춘 채로 Hierarchy · Inspector · Scene 탭을 봅니다. Step 은 한 프레임씩 나아갑니다.

Debug.Break()if (count == 5) Debug.Break();

코드가 Pause 를 누릅니다. 손으로는 놓치는 그 순간에 — 그 프레임이 끝나면 멈춥니다.

Inspector ⋮ → Debug

Inspector 오른쪽 위 ⋮ 에서 Debug 로 바꾸면 private 변수도 보입니다. Player 를 고르면 count 가 Play 중에 바뀌는 대로. 다 보면 Normal 로.

Hierarchy 검색 칸

PickUp 이라고 치면 그 이름만 남습니다. 12개여야 할 코인이 몇 개인지 바로 셉니다.

Play 중에 바꾼 것은 끄는 순간 돌아갑니다. 화면이 어두운 동안(Playmode tint) 바꾼 값은 시험입니다. 맞는 값을 찾았으면 컴포넌트 ⋮ → Copy Component, 끈 다음 ⋮ → Paste Component Values.

고치기 — 하나만, 그리고 같은 순서로 다시

원인을 눈으로 봤으면 고치는 것은 대개 짧습니다. 두 가지를 한꺼번에 바꾸면 무엇이 고쳤는지 모릅니다.

고친 것 — PickUp (12) 지우기

Ctrl + D 로 복제하고 옮기지 않은 코인이 PickUp (4) 와 같은 자리에 있었습니다. Play 를 끈 다음 지웁니다.

확인 — 3번 중 0번

같은 순서로 세 판. 한 판에 두 줄 같은 프레임이 없고, 코인이 남은 채 CLEAR 가 안 뜨면 끝. 확인이 끝나면 Debug.Log 줄은 지웁니다.

4번 중 3번이던 까닭 — 겹친 자리 코인을 마지막에 먹은 판은 Count 12 와 함께 코인도 다 없어져서, 이상해 보이지 않았습니다.

하면 좋음숫자 12 를 코드에서 빼기

레벨에서 코인을 더하거나 빼도 CLEAR 가 맞게, 씬에 있는 코인 수를 Start 에서 셉니다.

private int total; // 씬에 있는 코인 수 void Start() { rb = GetComponent<Rigidbody>(); count = 0; total = GameObject.FindGameObjectsWithTag("PickUp").Length; SetCountText(); winTextObject.SetActive(false); } // SetCountText 안 if (count >= total) { EndGame(true); }

SetCountText 보다 위에. 아래에 두면 total 이 아직 0 이라 첫 검사에서 바로 CLEAR 입니다. 켜진 코인만 세니 Start 에서 한 번만.

왜 후보부터

AI 는 Play 를 못 누르고 씬도 못 봅니다. 짐작으로 고친 코드는 맞는지, 다른 데를 망가뜨렸는지 모릅니다. 확인은 우리 손으로.

찾는 법Play 중에 이름 글자로 씬을 뒤짐끌어다 놓은 그 오브젝트를 기억
이름을 바꾸면null — 한 글자만 달라도그대로
꺼 두면null — 켜진 것만 찾음그대로
없으면 알려 주는 곳그 줄에서 NullReferenceInspector 칸에 None, Play 하면 UnassignedReference
다른 씬의 것못 찾음칸에 안 들어감 → 9주차 GameResult 처럼 static
왜 그대로인가

씬 파일은 오브젝트마다 번호를 붙이고, Inspector 칸에는 이름이 아니라 그 번호를 적습니다. 앞 편의 .meta 번호(GUID)와 같은 생각입니다.
